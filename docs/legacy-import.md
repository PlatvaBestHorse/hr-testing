# Импорт CandidateTester version 1

В банке вопросов администратору доступна кнопка «Импорт JSON». HR и оценщик не имеют доступа к этому этапу переноса. Кандидатские данные, старые попытки и результаты не импортируются.

## Порядок работы

1. Выберите исходный UTF-8 JSON, максимум 500 КиБ.
2. Нажмите «Проверить файл». Отчёт показывает ошибки с путями, количества, категории и параметры каждого теста. Банк не меняется; учитывается только технический лимит запросов.
3. Проверьте публикацию и показ баллов, затем введите «ИМПОРТИРОВАТЬ» и примените перенос. Все объекты создаются в одной транзакции организации из сессии.

Вопросы создаются опубликованными версиями 1. Это позволяет сохранить связи тестов на неизменяемые задания. Статус тестов берётся из `published`: true публикует тест, false оставляет черновик. Доступность теста в приглашениях не рассылает приглашения автоматически. Созданные вопросы и тесты доступны в обычных разделах, новые редакции создаются штатным редактором.

Поддерживается ровно предоставленный формат version 1, тип вопроса `single`. Неизвестные поля и другие типы не игнорируются: возвращается ошибка, чтобы не потерять содержимое. Для расширения формата нужны отдельные образцы. Никакие строки файла не исполняются как код или инструкции.

## Преобразование

| Исходное поле | Новая модель |
|---|---|
| question.id / test.id | Отдельная связь исходного ID с новым UUID в организации |
| type=single | single_choice |
| category | Категория той же организации по точному имени после обрезки краёв |
| difficulty | Лёгкий → 1, Средний → 3, Сложный → 5 |
| text, passage, explanation | Текст вопроса, вводный текст, пояснение |
| choices[].id, correct | Ключ правильного варианта сравнивается по ID |
| choices[].text | Подпись; порядок вариантов сохранён |
| questionIds | Ссылки на опубликованные версии и исходный порядок заданий |
| minutes | duration_seconds = minutes × 60 |
| passing | Точный процент с не более чем двумя десятичными знаками |
| shuffle | shuffle_questions; shuffle_options=false |
| showScore | show_candidate_score |
| Вес отсутствует | 1.00 на задание |

Существующие категории переиспользуются по точному имени; описания не перезаписываются. Вопросы с одинаковым текстом и разными ID не объединяются. Максимум 200 вопросов, 20 тестов, 200 заданий на тест; применяются обычные ограничения длины/вариантов. Проверяются уникальность ID вопросов/тестов/вариантов, ссылки правильных ответов, отсутствие повторов в тесте, сроки 1–480 минут, процент 0–100 и обязательные boolean-параметры. Показано максимум 100 ошибок за один запрос. Повторяющиеся JSON-ключи, лишние данные, неподдерживаемая версия и неизвестные поля отклоняются. API-тело ограничено 512 КиБ.

Это проверка структуры и сохранения исходных ключей, а не экспертиза логической правильности каждого задания. Автору нужно проверить содержимое и ответы перед использованием с кандидатами.

## Повторы и безопасность

Предпросмотр возвращает SHA-256 канонического типизированного содержимого. Изменение форматирования/порядка ключей не меняет сумму; изменение содержимого требует нового подтверждения. Это не SHA-256 исходных байтов файла; исходную сумму сохраняет оператор отдельно. API не хранит сам файл или предпросмотр; применение повторно валидирует `source`, сверяет `preview_sha256` и фразу подтверждения. Отдельного обязательного серверного объекта предпросмотра нет: авторизованный API-клиент может вычислить ту же сумму сам.

Сочетание организация + сумма уникально. Параллельный или повторный запрос получает ту же квитанцию с UUID, не создаёт дублей и повторного события аудита. Исходные ID уникальны отдельно для вопросов и тестов внутри организации. Если файл изменён и использует уже перенесённые ID, весь импорт отклоняется; автоматического обновления старых объектов или слияния нет. Для редактирования используйте новые версии в банке.

Организация блокируется на время применения, затем заново проверяются активные права/сессия. Нужны org_admin, разрешённый Origin и CSRF. Два одновременных импорта на API-процесс; 30 запросов на аккаунт/организацию и 120 на IP за 15 минут. Счётчики импорта отделены от почтового восстановления. В аудите одно событие `import.apply` с идентификатором квитанции, без банка, ключей ответов и исходного JSON. Межорганизационные связи защищены серверным контекстом и составными FK.

Миграция 0013 добавляет `import_batches`, `imported_questions`, `imported_tests`. Эти таблицы включены в полную зашифрованную копию базы; после восстановления повторный импорт остаётся распознаваемым. Прежние миграции не менялись. Старые копии требуют соответствующую версию CLI. Новые API описаны в [openapi.yaml](openapi.yaml).

## Предоставленный набор

[Отчёт по Logika_50_voprosov_CandidateTester.json](import-sample-report.md): 50 вопросов, 15 категорий, четыре теста. Исходные байты сохранены в закрытой `.imports/` вне Git. Не публикуйте приватный банк и правильные ответы вместе с исходниками. В текущем этапе реальный файл проверен и импортирован только в очищаемые временные организации; основной банк не изменён этим набором. Браузерная проверка применяет синтетический набор, затем архивирует только свои объекты.

Для повторной проверки предоставленного файла в изолированных тестовых организациях:

```bash
. scripts/cloud_env.sh
LEGACY_IMPORT_SAMPLE=/защищённый/путь/банк.json make integration
```

Без переменной используется синтетическая фикстура, включая опубликованный и черновой тесты. Проверка использует локальную development-базу и владельца для уборки только своих UUID; промышленную базу не использовать.
