# Облачная среда разработки

Рабочая копия находится в `/workspace/hr-testing`. Используйте её: каждая задача уже изолирована, создавать Git worktree не требуется.

В этой машине `/usr/bin/go` не является компилятором Go. Проверенный Go 1.26.9 установлен в `/workspace/.tools/go`; официальный архив проверен по SHA-256 из списка выпусков Go. Кэш и Docker buildx должны писать в доступную папку.

`compose.cloud.yaml` передаёт предоставленный прокси в сборку, разрешает его имя в контейнере и временно монтирует публичный системный CA-bundle через BuildKit. Проверки TLS, Go checksum database и npm integrity не отключаются; CA-bundle не копируется в образ приложения.

Перед командами разработки:

```bash
cd /workspace/hr-testing
. scripts/cloud_env.sh
```

Полный контейнерный запуск — `make up`. Быстрая разработка — `make db migrate`, затем `make api` и `make web` в отдельных процессах. Не запускайте одновременно контейнерный и локальный API на одном порту.

Актуальные функции и оставшиеся этапы — в docs/roadmap.md; прохождение, отчёты и последующие этапы уже реализованы. В текущей локальной базе создана одна организация и тестовый администратор; его данные находятся в `.env.admin.json` (0600, не выводить в логи). Не сбрасывайте пароль и не запускайте bootstrap повторно на существующей базе. Для чистой базы используйте `make admin` с интерактивным вводом; `make admin-dev` — только для локального тестового контура. Формы защищённого интерфейса открываются после входа через `/login`.

Проверки: `make check`, `make integration`, затем `cd frontend && npm run test:e2e` для контейнерного интерфейса. Для Vite задайте `E2E_BASE_URL` с портом 5173. Установленный Chromium позволяет проводить проверки без скачивания браузера с закрытого CDN.

`make integration` запускает и HTTP-проверки двух временных организаций; они удаляют только свои тестовые записи привилегированным локальным test-owner. Это не команда для production. Браузерные тесты читают локальные тестовые credentials напрямую, не выводят их и оставляют помеченные вопросы, тесты, кандидатов, вакансии и отозванные приглашения локальной тестовой организации.

После восстановления среды процессы нужно запускать заново. Наличие папки PostgreSQL не означает работающий сервис. `.local/postgres` и `.env` не входят в Git. Сохранённый снимок среды может содержать локальную тестовую базу; промышленные данные кандидатов здесь хранить не следует.

Проверяйте готовность локальными HTTP-запросами: `/readyz` у API и `/api/v1/status` через интерфейс должны вернуть `{"status":"ready"}`. В onboarding UI ссылки предпросмотра на loopback не поддерживаются.
