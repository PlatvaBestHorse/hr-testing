# Изображения заданий

У вопроса и каждого варианта ответа может быть одно необязательное изображение. Текст вопроса и текстовые названия вариантов остаются обязательными: они дают понятные подписи и доступные названия элементов выбора. Форматы PNG/JPEG; GIF, SVG, WebP и другие файлы пока не принимаются.

## Редактор

Администратор организации и рекрутер загружают файлы в редакторе вопроса, видят серверный предпросмотр и сохраняют новую версию. Пока идёт загрузка, сохранение, публикация, смена версии и изменение вариантов закрыты. Уход со страницы запрашивает подтверждение и отменяет незавершённый запрос; поздний ответ не меняет следующий вопрос. При ошибке замены прежняя картинка остаётся выбранной.

«Убрать изображение» снимает связь в открытом редакторе. Изменение вступает в силу после сохранения новой версии. Оно не удаляет файл предыдущих версий. В разделе «Неиспользуемые загрузки» можно удалить только файлы, не связанные ни с одной сохранённой версией или вариантом. Файлы текущего несохранённого редактора защищены от удаления в этом разделе; сервер проверяет сохранённые связи независимо от UI. Другой редактор может одновременно использовать файл: FK гарантирует либо сохранение связи, либо отказ удаления/сохранения, без повреждения версии.

Отмена редактирования, потерянный ответ загрузки или замена ещё не сохранённого файла могут оставить неиспользуемую загрузку. Список позволяет её найти и удалить. Автоматического удаления файлов нет. Список по 20 файлов, новые сначала. Лимит организации — 100 МиБ суммарных вложений и 1000 файлов; учёт сериализуется блокировкой организации, конкурентные загрузки не обходят лимит.

## Проверки файлов и хранение

На запрос допускается ровно один multipart файл `file`, без дополнительных полей. Максимум 5 МиБ исходных и нормализованных байт, максимум 4096 пикселей по стороне и 8 миллионов пикселей суммарно. API ограничивает размер тела; Nginx пропускает до 6 МиБ с учётом multipart. Одновременно обрабатываются максимум две загрузки на API-процесс, остальные получают 503 и могут повторить запрос.

Сервер сверяет заявленный MIME с сигнатурой/форматом, проверяет размеры до декодирования, полностью декодирует растр и заново кодирует PNG или JPEG с качеством 90. Исходные имена не сохраняются/не выдаются, метаданные и дописанные хвосты удаляются; выходной буфер тоже ограничен 5 МиБ. JPEG может измениться из-за повторного сжатия; EXIF-ориентация не переносится. Это структурная проверка и нормализация растра, **не интеграция с антивирусом**. Предусмотренное ТЗ сканирование внешним антивирусным сервисом остаётся отдельной задачей перед промышленным запуском.

Миграция 0010 добавляет приватные `attachments.data` (bytea), размеры и ссылки `image_id` в `question_versions`/`question_options`. Составные FK включают organization_id. Байты и метаданные вложения неизменяемы: роль `hr_app` не имеет UPDATE, дополнительный триггер запрещает UPDATE владельцу при обычных операциях. DELETE возможен только при отсутствии всех ссылок; FK сохраняют историю. Старые строки attachments без inline-данных остаются совместимыми и через эти маршруты не выдаются.

Публичного файлового каталога, внешних URL и путей, составленных из имени пользователя, нет. Выдача идёт через авторизованный API с no-store, nosniff, no-referrer, CSP sandbox, CORP same-origin и безопасным постоянным именем image.png/image.jpg. Это не удаляет уже скачанную пользователем копию, но новые запросы после отзыва/завершения отклоняются.

## Прохождение и отчёт

Версия вопроса фиксирует `image_id`; опубликованная версия и её варианты защищены существующими триггерами. Попытка ссылается на неизменяемые версии через свои test_items и порядок вариантов. Замена/удаление изображения в новом черновике не меняет опубликованный тест и начатую попытку. Кандидатский DTO добавляет только `image_id` (UUID или пустая строка); правильность, пояснение, SHA-256 и сведения загрузившего сотрудника не передаются.

Кандидат получает файл только по своему действующему приглашению и активной попытке до deadline. Файл должен принадлежать одному из вопросов или видимых вариантов именно этой попытки. До старта, после отправки/истечения срока, отзыва приглашения, по чужой попытке и для других файлов доступ закрыт. Кандидатский URL сохранён в существующей зоне без Nginx access/error URL-логов. HR-cookie не расширяет права кандидатской ссылки.

В подробном отчёте изображения доступны после submitted/expired. Оценщик видит их только по назначенной ему вакансии; прямой доступ ко всему банку ему закрыт. Проверка назначения применяется к каждому запросу файла. Неудачная загрузка отображается с кнопкой повтора; повтор не останавливает таймер. Изображения сохраняют пропорции и помещаются на экране 320 px.

CSV/XLSX остаются текстовыми отчётами и не встраивают изображения. Изображения доступны в веб-отчёте и в полной копии базы.

## API

| Маршрут | Назначение и доступ |
| --- | --- |
| POST /api/v1/images | PNG/JPEG multipart file; org_admin/recruiter, Origin и CSRF; ответ 201 с ID/MIME/размерами |
| GET /api/v1/images?page=1 | Неиспользуемые загрузки своей организации, 20 на страницу; org_admin/recruiter |
| GET /api/v1/images/{image} | Картинка банка своей организации; org_admin/recruiter |
| DELETE /api/v1/images/{image} | Удалить несвязанный файл; org_admin/recruiter, Origin и CSRF; 409 если используется |
| GET /api/v1/invite/{token}/attempts/{id}/images/{image} | Только изображение своей активной попытки |
| GET /api/v1/results/{id}/images/{image} | Картинка завершённого результата с проверкой организации/назначения оценщика |

В QuestionInput и options используется необязательное поле `image_id`, UUID или пустая строка. Чужой/несуществующий/не inline-файл отклоняется 422, а FK дополнительно проверяют организацию. Загрузка/удаление пишут image.upload/image.delete в аудит без имени файла или содержимого. Чтение картинки не создаёт отдельное событие: доступ к отчёту уже журналируется, повторные запросы `<img>` не засоряют аудит.

## Резервное восстановление

Байты находятся в PostgreSQL и автоматически входят в экспортированный снимок, pg_dump, зашифрованный архив и проверку SHA-256 содержимого attachments. Отдельного файлового каталога или второго несогласованного дампа нет. `make backup` проверяет восстановление с пятью защитными триггерами; интеграционная фикстура содержит PNG и опубликованную ссылку на него, после восстановления байты сравниваются напрямую.

Копии схемы 0009 не содержат новый этап. Для их восстановления требуется соответствующая версия кода/CLI; текущая проверка миграций намеренно откажет, не применяя миграции автоматически. Такие копии не удаляйте: восстановление предыдущего выпуска и последующее обновление — отдельная операторская процедура. Внешнее хранилище копий, S3 и раздельная политика хранения будущих внешних файлов не подключены.

## Проверки

Go проверяет PNG/JPEG, подмену MIME, повреждение, размеры, пиксельные пределы, хвосты и ограниченный выходной буфер. HTTP-интеграция — роли/CSRF, квоты, tenant/FK, неизменяемость файлов/версий, попытки/срок/отзыв, назначения оценщика, удаление и аудит. Vue проверяет multipart без ручного boundary/Content-Type, CSRF, ошибки/замену, удаление связи, отключённый редактор, отмену при уходе и повтор загрузки. Playwright desktop/320 px проверяет загрузку, блокировку сохранения, разные картинки версий, прохождение, перезагрузку и картинки отчёта. Полная интеграция резервных копий сравнивает восстановленный PNG.
