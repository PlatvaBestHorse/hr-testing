# Настройки организации, сотрудники и комментарии

## Организация

Все сотрудники видят название и срок новых приглашений в «Настройках». Только администратор меняет название, срок (1–365 дней) и статус. Приглашения, уже выданные кандидатам, сохраняют прежний срок. Изменения проверяются по ревизии: параллельное сохранение устаревшей формы возвращает 409.

Приостановка и архив требуют фразы «ЗАКРЫТЬ ДОСТУП». Сессии этой организации удаляются; сервер закрывает доступ сотрудникам и кандидатским попыткам по статусу организации. Данные сохраняются. Вернуть доступ из кабинета после закрытия нельзя.

Возобновление выполняет оператор, имеющий доступ владельца схемы, в согласованное окно обслуживания. Создайте закрытый JSON-файл с единственным полем `organization_id` и точным UUID нужной организации, затем из корня после активации инструментов:

```bash
python3 scripts/run_backend.py org-resume < /защищённый/путь/resume.json
```

Команда принимает только suspended/archived, запрещает роль `hr_app`, меняет ревизию, снова удаляет сессии и добавляет `organization.resume_cli` в аудит. Она не меняет пароли и не входит за пользователя. Возобновление не отзывает кандидатские приглашения навсегда: ещё действующие ссылки могут снова работать. Для постоянного закрытия конкретной ссылки используйте её отзыв. Проверка CLI выполняется на отдельной тестовой организации; основная организация не приостанавливалась.

## Приглашение сотрудника

Администратор выбирает имя, почту и роль в «Команде». По умолчанию отправляется приглашение на 48 часов; до выбора пароля членство имеет статус «Приглашён», вход невозможен. В текущем режиме письмо только локальное — см. [account-security.md](account-security.md). Альтернативно остаётся ручное создание с первоначальным паролем.

Повторная отправка доступна приглашённому сотруднику, отменяет прежнюю ссылку и выдаёт новую на 48 часов. Администратор может отключить членство и тем самым отменить доступ по приглашению. Ссылка привязана к аккаунту, организации и текущему хешу пароля; её применение проверяет актуальный статус. Повторное применение невозможно. Существующий глобальный email возвращает конфликт: чужой аккаунт автоматически не присоединяется к организации. Повторная отправка приглашения не используется для сброса пароля уже активного сотрудника.

Роли и активность существующих сотрудников меняются прежним способом с защитой последнего администратора. Активировать членство «Приглашён» напрямую нельзя: сотрудник должен завершить приглашение. Административные операции проверяют организацию и актуальные права; изменения отражаются в аудите без содержимого письма.

## Комментарии к результатам

В завершённом отчёте появился раздел комментариев. Доступ совпадает с доступом к отчёту: администратор и HR своей организации; оценщик только по назначенной вакансии. Чужая организация и снятое назначение закрывают и комментарии. У активной попытки комментариев нет.

Автор может изменить свой текст; удалить может автор или администратор. Изменение проверяет исходное `updated_at`, устаревшая версия возвращает конфликт. Текст — 1–5000 символов после обрезки краёв, не более 100 комментариев к попытке; выдача по 20. HTML выводится как обычный текст, без исполнения. В аудите сохраняются идентификаторы и действие, не тело комментария.

Комментарии не входят в кандидатскую выдачу и CSV/XLSX. Пользовательский текст может содержать персональные данные; текущая очистка контактов по сроку хранения его автоматически не обезличивает. Полное индивидуальное удаление и правила свободного текста требуют следующего этапа обработки персональных данных.

Миграция 0012 добавляет отдельные ревизию настроек и таблицу комментариев с составной связью организации/попытки. Прежние миграции не переписаны. Контракт — [openapi.yaml](openapi.yaml), проверки — [validation.md](validation.md).


С миграции 0015 полное удаление кандидата удаляет также все комментарии его результатов. Очистка только контактов по сроку комментарии не удаляет. Настройка версионируемых согласий/политики и порядок полного удаления — [personal-data.md](personal-data.md).
