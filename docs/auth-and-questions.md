# Вход, роли и банк вопросов

Реализован следующий этап ТЗ: сотрудники входят в свою организацию, администратор управляет командой, HR создаёт категории и вопросы. Оценщик может войти, но не имеет доступа к банку вопросов и команде; назначенные вакансии и результаты будут реализованы с соответствующими модулями.

## Учётные записи

Первый администратор создаётся `make admin` после `make db migrate`. Пароль вводится через getpass и передаётся Go-команде через stdin, не как аргумент процесса. В базе сохраняется Argon2id: 64 MiB памяти, 3 итерации, 2 потока и случайная соль. Минимальная длина пароля — 12 символов, максимум — 1024 байта.

Участников создаёт администратор в разделе «Команда». Сотруднику задаются начальный пароль и роль; почтовая отправка и самостоятельная смена пароля пока не реализованы. Смена роли или отключение участника завершает все его сессии в этой организации. Последнего активного администратора нельзя отключить или понизить в роли. Параллельные изменения команды сериализуются блокировкой строки организации.

Сессии имеют случайный 256-битный токен и фиксированный срок 8 часов. В PostgreSQL хранится только SHA-256 токена. Cookie имеет HttpOnly, SameSite=Lax и Secure в HTTPS-режиме. Роль, состояние сотрудника, участие и состояние организации проверяются при каждом запросе. В браузере нет паролей и session token в localStorage. POST/PATCH/DELETE требуют разрешённый Origin и текущий X-CSRF-Token; вход также проверяет Origin.

Попытки входа ограничены на 15-минутном окне: 10 на почтовый адрес и 60 на адрес подключения. В качестве идентификаторов записываются хеши. Лимит хранится в БД, поэтому рестарт API его не сбрасывает. X-Forwarded-For не принимается от произвольного клиента; за Nginx IP-лимит общий для подключений прокси. Argon2-операции входа дополнительно ограничены четырьмя одновременными вычислениями. Подробную политику доверенных прокси и распределённых лимитов нужно уточнить перед production.

## Вопросы

Список поддерживает поиск по тексту, категорию, статус и страницы по 20 записей. Категорию с привязанным вопросом, включая архивный, удалить нельзя.

Вопрос состоит из вводного текста, формулировки, необязательной категории, сложности 1–5, вариантов и пояснения для HR. Варианты — 2–10, без пустых/повторяющихся формулировок. Типы:

- `single_choice`: ровно один правильный вариант.
- `verbal_tfu`: фиксированный порядок «Верно / Неверно / Недостаточно информации», ровно один правильный вариант.
- `multiple_choice`: минимум два правильных варианта; частичные баллы будут определяться модулем прохождения.

Создание даёт версию 1 и статус черновика. Каждое следующее сохранение добавляет новую версию, не перезаписывает старую и требует актуальный `base_version_no`. Параллельные сохранения блокируют карточку вопроса; устаревший запрос возвращает 409. Публикация повторно валидирует сохранённую редакцию в транзакции, фиксирует её и пишет аудит. Триггеры запрещают UPDATE/DELETE опубликованных редакций и изменения их вариантов. Просмотр прошлой редакции доступен через `version_no`. Архив сохраняет историю и запрещает новые редакции этой карточки.

Ключи ответов и пояснения доступны только авторизованным HR/администраторам. Предпросмотр в редакторе скрывает их визуально; это не публичная страница кандидата. Анонимный доступ к банку запрещён. Кандидатские API с отдельными DTO будут реализованы позже.

## Локальный тестовый администратор

`make admin-dev` создаёт случайные локальные credentials в `.env.admin.json` с правами 0600. Не печатайте файл в логи и не добавляйте в Git. Уже подготовленная облачная машина содержит эту тестовую учётную запись. Она используется и браузерными тестами.

Для восстановления **только этого локального тестового аккаунта**, если bootstrap ранее прервался после подготовки файла:

```bash
python3 scripts/create_admin.py --dev --reset-dev
```

Команда применяет сохранённый тестовый пароль к локальному аккаунту и завершает его сессии. Не используйте её для пользовательской или промышленной базы. Существующий файл не перезаписывается.

Локальная административная смена пароля произвольного существующего сотрудника доступна Go-командой `cmd/set-password`: JSON с email/password передаётся через защищённый stdin при наличии доступа к БД. Она не выставлена в HTTP API, отзывает все сессии аккаунта и пишет аудит. Не передавайте пароли аргументами shell и не храните их в отслеживаемых файлах.

## Миграции и проверки

Добавлены `0003_auth.sql` и `0004_question_publication.sql`; миграции 0001/0002 и исходные документы сохранены без изменений. Readiness требует миграцию 0004.

`make check` проверяет сборки и модульные тесты. `make integration` дополнительно выполняет реальный HTTP-сценарий с двумя временными организациями: вход, CSRF, роли, отсутствие доступа к чужим объектам, сохранение, публикация, триггеры, историю, параллельные версии, последний admin, отзыв сессий, архив и ограничение входа. Для очистки только тестовых записей применяется отдельная транзакция локального test-owner с maintenance-привилегиями. Приложение таких привилегий не имеет.

Браузерный сценарий проверяет редактор и вход на desktop и мобильном Chromium. Все цели WCAG, остальные браузеры и промышленная защита не считаются проверенными этим этапом.
